# Image credits and photo provenance

**Status: every photograph in `public/photos/` is a real photograph sourced
from Pexels.** No placeholder or template imagery remains, and there is no
AI-generated imagery anywhere in this project.

- **Source:** [Pexels](https://www.pexels.com/) — the only host permitted by the
  build brief.
- **Licence:** the [Pexels licence](https://www.pexels.com/license/) — free for
  commercial and non-commercial use, no attribution required, no watermark.
  One file (`produce/chard-beetroot.jpg`) comes from Pexels' legacy
  [Creative Commons](https://www.pexels.com/creative-commons-images/) set (CC0),
  which carries the same commercial-use grant.
- **Subject:** the brief's requirement — East African farmers, produce and
  market settings — is met across the set. Each slot's subject is recorded in
  the table below and in `scripts/fetch-photos.mjs`.
- **Re-download:** `npm run fetch:photos` (see *Reproducing the set* below).

> **Attribution is recorded here as good practice, not obligation.** The Pexels
> licence does not require it. Nothing in this file needs to ship with the site.

## Known subject-matter gaps

These are honest limitations, not oversights. Every one is fixable by
re-running `npm run fetch:photos -- --force` against a different Pexels id in
`scripts/fetch-photos.mjs` — no code change is needed.

| Slot | Gap | Why it is still shipped |
| --- | --- | --- |
| `farm/packhouse-grading.jpg` | Shows a **non-African** packing crew. | Pexels' searchable supply of African packhouse and grading-line photography is thin. The brief's requirement for this slot is *"produce being sorted or graded, crates or tables visible"*, which the photograph does meet exactly. |
| `farm/harvest-greens.jpg` | Hands only — no person visible, so neither African nor non-African. | The brief asks for *"hands holding freshly cut greens"*. Hands-only framing is precisely that. |
| `produce/*.jpg` | No African visual context — vegetables and leaves only. | Produce close-ups have no people in frame by design. |

The strongest candidates for replacement are `farm/packhouse-grading.jpg` and,
if a wider choice matters more than exact framing, `farm/harvest-greens.jpg`.

### Repeated imagery across the catalogue

`src/data/produce.ts` has **28 catalogue lines sharing 13 photographs**, so the
same image appears on several cards. Alt text was rewritten to describe **the
photograph**, not the product line, precisely because one photo represents many
products — an alt of "Hass avocados harvested at the Meru Ridge Farm" over a
picture of kale would be worse than useless to a screen-reader user.

For a stronger catalogue, source one image per produce line and point that
line's `image` field at it. That is a content task, not a code change.

## Reproducing the set

```bash
npm run fetch:photos -- --list    # print the manifest: slot → Pexels id → size
npm run fetch:photos              # download any missing slot
npm run fetch:photos -- --force   # re-download and re-crop every slot
```

`scripts/fetch-photos.mjs` requests each photo from `images.pexels.com` at the
exact pixel size the site declares, so cropping happens on the Pexels CDN and
no image library is required. The script refuses to write a `.webp` slot unless
the CDN actually returns WebP, so a JPEG can never end up served under a
`.webp` extension.

If the environment cannot reach `images.pexels.com`, open the Pexels page from
the credits table above, download at full size, and crop to the size printed by
`--list`.

### Sizes, and why they are what they are

| Group | Delivered | Declared in code | Rendered at |
| --- | --- | --- | --- |
| `farm/farm-field-aerial.webp` | 1200×630 | 1200×630 (OG) | Full-bleed page-title band, AR panorama, OG card |
| `farm/farmer-harvest-kale.jpg` | 600×800 | 1200×630 (metadata only) | ~400 px wide — 600 px is ample |
| `farm/*.jpg` | 800×600 | 4:3 `aspect-ratio` | up to ~400 px wide |
| `produce/*.jpg` | 800×600, 1000×750 | 4:3 `aspect-ratio`; hero poster declares 900×900 | ~400 px cards, up to 560 px poster |
| `people/testimonial-*.jpg` | 400×400 | 1:1 `aspect-ratio` | 48 px avatar |
| `people/team-*.jpg` | 600×600 | unused | — |
| `blog/*.jpg` | 640×400 | 640×400 attributes | ~360 px card |

The full farm set was re-cut to a strict 4:3 and the blog set to 16:10, matching
what the CSS and the `width`/`height` attributes already declared. Previously
several files were square where the markup said 640×400, which would have
shifted layout on load.

Everything is under 100 KB; the whole `public/photos/` tree is ~1.4 MB.
